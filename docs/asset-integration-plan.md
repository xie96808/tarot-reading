## 1. 用户反馈与已确认事实

用户打开现有网页后反馈：“桌子”“桌布”始终没有适配。
此反馈作为 P0 缺陷处理，不再将同路径替换图片视作接入完成。
尚待实际浏览器复现具体视口、阶段及表现，复现是实施第一步，不要求用户重复操作。

代码与素材检查确认：
- public/table 的桌子、绿色桌布、手部和实体牌均烘焙在完整照片中；桌布不是可独立缩放的 DOM 层。
- surface 和三个手势图都是 1600×900、不透明图片，构图及桌布位置不一致。
- TableScene 的容器桌面比例为 16:10，720px 以下改为 4:5；所有照片 object-fit:cover，横图在手机上发生大幅裁切。
- .felt 是交互内容容器，并不是照片里的绿色桌布；其固定百分比定位并未绑定素材中的实际可用区域。
- 手势层 z-index:4，交互内容 z-index:2，手势完整照片以 0.96 不透明度覆盖内容。
- 手势动画平移/旋转整张照片，桌子与桌布也会运动。
- spread 使用固定最小高度及绝对定位内容，牌阵另有 1023px 断点；需要统一审核高度、裁切及断点策略。
- 浏览器缓存是否参与问题尚未确认，不将缓存当作既定原因。

## 2. 目标与非目标

目标：桌子构图稳定，桌布与牌阵的空间关系合理；所有交互可见可操作；新增资源融入既有阅读与分享流程。
非目标：不修改抽牌算法、随机源、分享协议或保存规则；不新增搜索、收藏功能；不为使用素材强行制造空状态。

## 3. 视觉与布局决策

### 3.1 照片模式：洗牌、切牌

- 将完整照片作为唯一场景底层，不再解释成透明手部覆盖层。
- 照片优先保持原始 16:9 构图，小屏不再强制裁成 4:5；操作区按内容自然增高。
- 保留长按、自动洗牌、切牌滑块等现有操作及文字反馈。
- 代码牌堆如用于反馈，应移动至独立示意区域并标明用途，不与照片内实体牌重叠；实施前逐项审查 ShuffleTable/CutTable 的状态信息，禁止直接删掉反馈。
- 去除整图视差、旋转和上下漂移；构图不同的状态图优先直接切换，只有实测无明显重影时才使用短淡入淡出。
- 减少动画模式保持稳定画面及等价操作，不改变抽牌结果；明确是否保持现有无手势图策略并同步测试。

### 3.2 牌阵模式：发牌、翻牌、牌阵阅读

- 使用 surface 图作为桌面背景，牌面、焦点和按钮始终在上方。
- 内容决定桌面区域高度，不再用固定高度加绝对定位强行容纳所有牌阵。
- 用明确的素材可用区域参数校准绿色桌布和牌阵中心；分别验证单张、三张、凯尔特。
- 小屏保留现有逐张阅读能力，发牌概览也必须在边界内；文字和导航可放在桌面区外。
- 优先保留现有素材。若照片中的桌布比例确实无法容纳长牌阵，则改用独立木桌背景与可伸缩桌布层；这是素材拆分决策，不用继续拉伸整图掩盖问题。
- 不直接用 CSS 伪桌布盖在原有绿色桌布上，避免出现两块桌布；如需拆层，先准备干净背景并单独验收。

3. 保存改前截图，记录容器尺寸、图片 naturalWidth/currentSrc、裁切、桌布可用范围和控件边界。
