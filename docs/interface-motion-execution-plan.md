# 烛下塔罗界面动效执行计划

版本 1.0 · 2026-10-06  
依据：[界面资源与动画优化设计](./interface-motion-optimization-spec.md)  
代码基线：本地 `HEAD`。线上 `tarot.xieyw.top` 使用了本地没有的桌垫与手部文件，本计划不把本地组件当成线上素材的覆盖稿。

设计文档继续当体验和验收的依据。本文只补执行时必须先定死的契约、批次边界和完成定义。冲突时，体验决策以设计文档的“本轮决策”为准；实现顺序和下面三条契约以本文为准。

## 契约

1. **暂停文案按牌位生成，第一版不改词库合同。** “第一张是过去”来自 `PauseSheet` 固定读 `pauseDoorLead`，不看来自哪一张。修复只改引导句，按 `past` / `present` / `future` 生成。`刚才你没有点`、`沿着刚才那一步` 仍由 `src/data/lexicons/zh-1/pauses/validate.ts` 锁定，留在批次 B，和验证器、十个词库文件、相关测试一起改。不在 `zh-CN.ts` 里做同义词替换。
2. **新局与旧局的场景字段先不动。** 批次 A、B 不改 `sceneId`、`sceneLocked`、暂停答案和分享编码。旧推门、过手会话照原样恢复。取消“必须先选推门或过手”、标准翻牌，以及暂停不再挡住翻开，都放在批次 B，并单独写迁移。随机算法、正逆位结果、切牌、隐私默认保持不变。
3. **“不太贴近”第一版不改后续牌文。** 可选回应可以保留，但不能推断心理事实，也不能重写后面的牌义。真要按回应改讨论，另开一批。

洗牌提交等待也不为了凑视觉时长删掉。收齐可以落在约 1600ms，`commitShuffle` 没完成时继续显示真实等待。

## 批次

### A · 证据已经对齐的修复（本批执行）

- 引导句随 `positionId` 变化。过去是“第一张：先看看过去。”现在是“第二张：看看现在。”
- 暂停面板移出牌桌，桌垫不再被对白拉高。手机上的摊牌舞台改为包住牌，不再用 560px 最小高度把桌垫拉长。
- 手掌画在舞台内。舞台用 `overflow: clip` 裁切装饰，不在 `body` 上藏溢出。
- 洗牌、切牌、发牌、翻牌不再整段淡入，也不再 `scrollIntoView` 回章节标题。翻牌时不把焦点夺到暂停标题。
- 推门从半翻到全翻的 CSS 改成祖先选择器。`data-scene-from` 写在外层，原来的规则匹配不到 `.inner`。
- 预载和正在看的牌使用同一套 `sizes`。场面进入半翻之前，先对这张候选图 `decode()`。失败保留同一张牌，并给出重试。
- 不改牌图、桌面木纹、手部文件，不引入视频。

完成定义：相关单元测试通过；三张牌流程里第二张引导不再说“第一张是过去”；390px 下文档没有横向溢出。未测的真机、帧率和弱网保持未测。

### B · 路径

合并“我准备好了”、问题、选阵里的重复确认。默认标准翻牌，推门和过手不再挡住开始洗牌。旧会话仍能读。半翻不再是必经提问。逆位保持抽到的方向，“转正看图”只改观看角度。结果正文只留一份。同时改暂停词库合同。业务回归通过后再进批次 C。

### C · 连续动作

洗牌、切牌、发牌、翻牌共用一个舞台和牌堆锚点。松手从当前姿态收齐，不跳回关键帧 0。先交付无手版本。手部要同一人物、同一光向、接触锚点稳定，并且不撑开页面；不合格就继续用无手翻牌。这一批才制作手势样片，不在 A 里生成新图。

### D · 资源与发布

字体先看网络瀑布，再决定标题子集。生产构建上对比性能。真机、五人试用和帧预算是发布门，不是每一批的合并门。未测项保持未测。不自动提交、推送或部署。

## 验证

每一批至少跑：

```sh
npm run test
npm run lint
```

涉及阅读流程时补跑对应的 Playwright 用例。`npm run test:e2e` 指向本地 `127.0.0.1:3100`，不打线上。`npm run build` 的 prebuild 会执行 ingest，只在需要发布验证时跑。
